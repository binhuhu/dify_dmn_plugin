# v0.5.0（已发布，2026-10-23 UTC）

Historical version record. Test counts and validation status below describe that version, not the current review branch or a current deployment.

在上一版本之上的功能变化：

- `73c0f65` 受理路由表存插件存储、在插件里编辑：`evaluate_decision` 遇到 `PLUGIN_STORAGE` 存储引用时运行时取表编译；端点组「路由表编辑」（编辑口令）。
- `bd76d7b` 路由表 v2（`dmn-json.route-table/v2`）：表里带场景目录和方案登记，编辑页按场景配置去向（方案应用 / 转安全 / 知识库 / 无方案）；新工具 `invoke_solution` 按 app_id 调已登记的方案应用。
- 版本号升到 0.5.0（manifest、`scripts/stage-builtin.py`、兼容脚本和测试里的版本断言）。
- `8c906f1` `8c17eb6` PSN 结构加 KNOWLEDGE 族（Q1–Q4，咨询作答应用用；只动 `psn` 离线工具与 schema，不进运行时路径）。
- 发布提交：`decision_executor.py` 只做 ruff 格式化，让 CI 的 `ruff format --check` 通过。

合同、约束和上线顺序见 [route-table-editing.md](../route-table-editing.md)。

## 安装时会多问的权限

| 权限 | 用途 |
|---|---|
| `storage`（16 MiB） | 路由表和它的历史版本 |
| `endpoint` | 路由表编辑页（0.4.2 已有，用于结构展示页） |
| `app` | `invoke_solution` 调本工作空间里已登记的方案应用 |

## 打包（发布者执行，同 0.4.2 的做法）

1. 推送 main，确认 GitHub 上 Checks 对发布提交是绿的。
2. 从该提交的干净 `git archive` 运行 `python scripts/stage-builtin.py <staging 目录>`，再用官方 Dify CLI 打包：`dify plugin package <staging 目录> -o hu8627-dmn_json-0.5.0.difypkg`。
3. 打 annotated tag `v0.5.0` 指向该提交，发 GitHub Release，唯一资产是上面的包；记录包大小、SHA-256、Dify checksum 和插件身份 `hu8627/dmn_json:0.5.0@<checksum>`。
4. 在 Dify 宿主 的 目标工作空间把 `dmn_json` 从 0.4.2 升级到 0.5.0（From GitHub），同意新增权限；新建「路由表编辑」端点并填编辑口令。

## 装好后核对（只读）

- 插件列表里 `hu8627/dmn_json` 版本 0.5.0，声明的权限含 `storage`、`endpoint`、`app`。
- 内置工具多了 `invoke_solution`，共 6 个。
- 端点列表里有「路由表编辑」端点。
- 不含存储引用的既有定义包不会通过本功能读取表存储；升级兼容性仍应按部署环境验证。
