## 修复：资源表引用校验可被绕过（10-29 v0.5.3 发布前核验发现）
- 复现：先把某张路由表从资源表的 `route_tables` 去掉，再删该路由表仍引用的目标 → 保存成功；v3 路由运行时报 `ROUTE_TABLE_UNKNOWN_RESOURCE`。
- 原因：存资源表时只核**新**文档列出的路由表。
- 修法：连同已存版本列出的路由表一起核；仍引用本资源表的路由表不许从 `route_tables` 去掉（新拒码 `RESOURCE_TABLE_ROUTE_DROPPED`），要先改路由表。
  不变式：引用某资源表的路由表一定列在它的 `route_tables` 里（路由表存时本来就要求）。
- 测试：`tests/test_stored_tables.py::test_a_resource_table_cannot_drop_a_route_table_that_still_names_it`（先红后绿）；插件全套 1039 过、72 跳过；ruff 无报。
- 影响：平台身份随之改变，分诊 D 三个工具节点要改钉到 0.5.4 的身份。

## 回滚

- 只回插件（存储里只有新表、路由表没有 RESOURCE 行）：旧版不读 `p2.*`、`supplement.*`、`*.resource`，无副作用。
- 路由表一旦存进 RESOURCE 行：先在编辑页把路由表存回上一版（不含 RESOURCE 行与 resource_table），再回插件；0.5.2 遇到 RESOURCE 行会报 `ROUTE_TABLE_TARGET`，所有读路由表的流程都会失败。
