# v0.5.8（候选：未发布、未装机）

WO-115。依据：ESE 复评 N-02——ESE 方案的失败出口仍是代码节点，沙箱失败时平台错误文本 / 堆栈经子流程 `error` 回到 `invoke_solution` 回执（≤300 字）；券切现网（路由表 v3 `06a37832`）前在我方关口堵上。
基于 v0.5.7（包源 `ab65ea2`，记录提交 `4e1f171`）+ `1e2628c`（测试）+ `ed3e03c`（修）。

**0.5.8 与 0.5.7 的差异只有两段回执文本**：`invoke_solution` 失败回执的 `error_message` 不再转发子流程的原始错误与平台异常文本，改成固定说明。

## 改了什么

| 改了什么 | 为什么 |
|---|---|
| 子运行状态不是 `succeeded`（`dmn_client/solution_invoke.py`）：`error_message` = 「方案运行没有成功结束（`<run_status>`）」；`error_code` 照旧 `SOLUTION_RUN_FAILED`。0.5.7 是子运行的 `error` 原文（没有时是 `run_status`） | 方案代码节点沙箱失败时，`error` 里是平台错误文本 / 堆栈，可能带运行里的值；不该经回执进交付编排、侧栏与日志 |
| 平台调用抛异常（开调即抛、流中途断、结束事件后断）：`error_message` = 「调方案没有成功（`<异常类名>`）」；`error_code` 照旧 `SOLUTION_INVOKE_FAILED`。0.5.7 是 `str(exc)` | 同上：异常文本可能带平台内部信息与入参 |
| 测试 `plugin/tests/test_invoke_receipt_no_raw_error.py`（`1e2628c`，33 条）：子运行失败 / 平台异常的 `error` / 异常文本里放堆栈样文本与假 uid（`Traceback … uid=1234567890123`）→ 整份回执与工具发出的每条消息里都没有，`error_code` 不变，子运行编号等照旧；其余 12 种回执（成功、阻塞式成功、无结束事件、未登记、app_id 不对、入参缺 / 多、非字符串、非 JSON、表缺、存储坏、非 v2）整份逐字钉成 v0.5.7 在同一输入上的输出 | 钉住只改这两处 |
| 版本号 0.5.7 → 0.5.8：`builtin/manifest.yaml`、`scripts/stage-builtin.py`、测试里的版本断言（`plugin/tests/test_dsl_sdk.py` 3 处、`plugin/tests/test_json_table.py` 1 处）、兼容脚本 `scripts/compatibility/{builtin,dsl}_stdio.py`（与 0.5.7 同一组位置） | 发布 |
| `docs/route-table-editing.md`「调用方案」加一行 0.5.8 说明；本发布说明 | 发布 |

查失败原因：回执里的 `child_workflow_run_id`（与 `child_workflow_id`、`run_status`、`elapsed_time`）照旧，按它去 AgentHub 看那次方案运行。

## 不变

回执的键与顺序、`status`、全部错误码、其它错误码的文本、只调 `CURRENT`、成功回执、工具 8 个与全部入参出参、路由表 v1 / v2 / v3、决策表 / 补充表 / 资源表、`routing-table/v2` / `v3` / `v4` 编译模型、编辑页、存表 / 读表 / 存前闸接入点——与 0.5.7 逐字节相同。
插件代码里只改 `plugin/dmn_client/solution_invoke.py`（两处回执文本 + 模块说明一段）；`builtin/` 只改 `manifest.yaml` 的版本行。
行为比对（WO-102 的 `scripts/compare-behaviour.py`，base `v0.5.7` / head `ed3e03c`，同一组输入）：2836 例里 2818 例逐字节相同；不同的 18 例全是 `invoke.*` 的 `$.receipt.error_message`，正好是三种失败形态（`run-failed`、`platform-raises`、`finished-then-stream-breaks`）× 6 种表。路由求值 2700 例、存表 16 例、两个工具的消息 34 例全同。
