# v0.5.7

v0.5.7 是版本升级及编辑页回归测试强化。与 v0.5.6 相比，插件运行代码完全相同，没有新增运行代码修复。原包只变更 manifest.yaml 和 pyproject.toml 的版本行。

## 变更

新增 4 项编辑页保键回归测试：v2 修改路由去向、v3 修改路由去向、v3 修改方案登记状态、v2 携带资源表升级 v3。测试覆盖 resource_table、顶层键、路由行键和未修改存储元数据的保留。编辑页自 v0.5.5 起已有的保键行为保持不变。

## 验证

本次云端在精确标签源码及保留远端历史的合并主线上分别运行 scripts/check.sh：engine 99 passed；plugin 1208 passed / 1 skipped；manifest 权限检查、ruff check 和 ruff format --check 全通过（ruff 0.15.7）。精确源码的 viewer 54 项通过，Chromium 153 桌面/移动浏览器回归通过，保持浏览器 sandbox。

原包 74 个文件全部与精确标签源码经 stage-builtin.py 生成的文件逐字节一致；staging 额外的 .env.example 未打入包。使用官方 Dify CLI 0.6.10 和独立内容算法核对 checksum。保持供应原包字节，没有重新打包。

## 已知限制及迁移边界

- 发布不等于迁移或宿主验收。AgentHub / Dify 目标宿主安装与运行：NOT_RUN；未修改配置、工作流、应用或插件表。
- 首次保存 route-table/v3，以及下游切换 routing-table/v4，均需要单独授权。v3/v4 数据落地后，旧版本插件可能无法读取；不得把回滚至更早版本视为无副作用。v0.5.6 与本版运行代码相同。
- RESOURCE 行落地后，v0.5.2 不能直接读取相应数据。
- gate_report 只是与 hash 绑定的接入钩子，本版没有真实 gate 运行逻辑。
- 存储仍非原子 CAS；乐观版本检查和 save_id 不提供原子并发保证，并发保存仍可能双方成功，后写覆盖版本/head。
- 跨表状态检查仍受既有 dispatch.route 与已保存路由表范围限制；SHADOW 状态语义不变。
- 共享工作流工具存储需要单独配置维护应用及 store_app_id；留空的端点私有存储仅适合调试。能够搭流程或运行维护应用的工作空间成员可能通过工具修改路由，编辑口令只保护编辑页。
