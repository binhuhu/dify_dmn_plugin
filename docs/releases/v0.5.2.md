# v0.5.2（准备中，未打包、未发布）

0.5.1 在 AgentHub（ESE_sd）实测时发现两件事，本版修：

| 问题 | 实测证据 | 改了什么 |
|---|---|---|
| 编辑页打不开 | 打开端点地址出来的是「定位与解决 · 结构视图」。编辑器和结构视图都声明了 `GET /`、`GET /<path:route>`；SDK 把两组端点放进同一张 werkzeug 路由表，结构视图在前，所有 GET 都到它那里，只有 POST 到编辑器 | 编辑器挂到 `/routes/` 下（`GET /routes`、`/routes/`、`/routes/<path:route>`，`POST /routes/<path:route>`），`/routes` 跳到 `routes/`。编辑页地址 = 端点地址 + `/routes/`。新测试 `test_endpoint_routing.py` 按 SDK 的方式建路由表，并保留 0.5.1 的写法作反例（`3f57a51`） |
| 编辑页存的表，流程里读不到 | 端点存了 `probe.route`（端点里读回是第 1 版），草稿流程 `evaluate_decision` 连跑 7 次都是 `ROUTE_TABLE_MISSING`：AgentHub 上端点和工具看到的插件存储不是一份 | 新工具 `route_table_store`（路由表存取）在工具存储里读写；端点新设置「维护应用 ID」，填了以后编辑页的读、存都经插件调用「路由表维护」应用、由它的 `route_table_store` 节点落到工具存储。新测试 `test_route_store.py` 用两份分开的存储复现实测情形：编辑页保存后，决策工具能读到 |

内置工具变成 7 个，最后一个是 `route_table_store`。版本号 0.5.2（manifest、`scripts/stage-builtin.py`、兼容脚本和测试里的版本断言）。

合同、维护应用的搭法和退路见 [route-table-editing.md](../route-table-editing.md)「AgentHub 上：端点的存储 ≠ 工具的存储」。

## 装好后要做的

1. 在 ESE_sd 升级到 0.5.2。
2. 建并发布「路由表维护」应用（只有一个 `route_table_store` 节点），把 app_id 填进「路由表编辑」端点的「维护应用 ID」。
3. 编辑页地址改用 `https://agenthub.intra.xiaojukeji.com/e/<hook>/routes/`。

本机：plugin pytest、ruff、manifest 权限闸都过。AgentHub 上：端点能不能调应用（「调用应用」权限）、`invoke_solution` 调方案、宿主时限都还没测；不能调应用时编辑页会报 `ROUTE_STORE_APP_FAILED`，退路是直接运行维护应用。0.5.1 的已知问题（并发保存可能两边都成功）本版没改。
