# v0.5.14

- Add optional table declarations (`declare`) to decision, supplement, resource and route tables: role, stage, parameters (business name, source, domain), outputs, state meanings, per-rule rationale (`rows.why`, optional `rule_sha256`) and row-order priority for FIRST tables.
- A declaration is checked against the table on save, never read at evaluation and not part of `content_sha256`. Tables without one are stored exactly as in v0.5.13.
- `TRANSITION` declarations describe a table as it is. `STANDARD` declarations (decision tables) enforce the standard output: shared states, `data` = `result` + `note`, `result.actions`, no hand-written `result.rule_id`, and a check on customer-facing `result.texts.customer`.
- A save that leaves `declare` out keeps the stored declaration (and must still fit it); `declare: null` removes it. A rule changed after its rationale was written returns a `RULE_WHY_STALE` warning instead of a refusal.

- Save validation rejects malformed declaration types and mismatched keyed-table output types/values. Route output declarations validate field names and fixed compiled types; resource-dependent route values are not inferred. JSON enum checks distinguish booleans from numbers.
- Runtime evaluation ignores declarations, including malformed or stale metadata, while retaining content validation. A failed preservation read refuses the save rather than losing metadata. Rule provenance remains in `selected_rule_ids`; no `result.rule_id` is injected.

Production installation and acceptance have not been completed.
