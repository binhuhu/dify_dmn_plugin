# v0.5.6（候选：未发布、未装机）

WO-79。路由表 `solutions{}` 成为方案登记的唯一维护点。依据：Brian「dify上的配置是唯一来源」「场景方案路由策略一定是可以显性查看和编辑的」「场景关联实体要策略配置化 同样受理  路由也是」；清晰度评审 §4「方案登记」；深度评审 S9 / D2-01。
基于 v0.5.5 记录提交 `9e250bd`（包源 `36b81d4`）。

今天（0.5.5）：路由表 v2 的 `solutions{app_id → {name, inputs}}` 只是白名单 + 开始变量；方案能不能调，由分诊 / 交付编排图里内嵌的登记表决定（分诊 admission-input 的 `REGISTRY=`、交付编排 29 个 bundle 节点的 `config.registry`，共 30 份），存一版路由表不会让新方案上线。

## 改了什么

| 改了什么 | 为什么 |
|---|---|
| **路由表 v3**（`dmn-json.route-table/v3`，`dmn_client/route_table.py`）：与 v2 同一份文档，`solutions` 每项多登记字段——`status`（必填：`CURRENT` / `CANDIDATE` / `GATED` / `SHADOW` / `RETIRED`）、`gate_code`（`GATED` 必填；`SHADOW` 可写）、`request_contract`（如 `场景方案调用/v4`）、`topics[]`、`intents[]`、`invocation_scope`、`priority`、`package_id`、`target_handoff`。存时每项补齐全部键（没写的是 `null` / `[]`），话题 / 诉求保持登记顺序。`input_bindings` **不进插件表**（拒收，`ROUTE_TABLE_INVALID @solutions.<app>.input_bindings`）：交付编排怎么组请求是交付编排的事，按 `request_contract` 选适配 | 方案登记只在一处维护；新方案 / 翻闸 = 编辑页存一版 |
| **校验**：`CURRENT` 必有 `request_contract` 与非空 `topics` / `intents`（`ROUTE_TABLE_SOLUTION_INCOMPLETE`）；`GATED` 必有 `gate_code`（`ROUTE_TABLE_GATE_REQUIRED`），`CURRENT` / `CANDIDATE` / `RETIRED` 不写闸；**同一个应用在两张路由表里状态（status + gate_code）不能不同**（`ROUTE_TABLE_SOLUTION_STATUS_CONFLICT`；存储键 `route-table-index` 记 0.5.6 起存过的路由表，`dispatch.route` 总在比；v2 表按全部 CURRENT 算）；**v3 表不能存回 v1 / v2**（`STORED_TABLE_SCHEMA_CHANGED`：旧格式把每个方案都当 CURRENT，会放开被闸挡着的方案） | 规格第 4 项；不让「选哪张表」或「旧格式覆盖」决定一个被闸挡着的方案跑不跑 |
| **v2 照旧可读**：每个方案按 `CURRENT`、无闸、其余未声明读（`solution_entry`）；v2 文档的存储形态与 `content_sha256` 不变 | 现网 `dispatch.route` 是 v2；装 0.5.6 不改它能调的方案 |
| **`invoke_solution` 只放行 `CURRENT`**（`dmn_client/solution_invoke.py`）：被闸挡着的（`GATED`，或带闸的 `SHADOW`）REJECTED `SOLUTION_GATED`，其余非 CURRENT REJECTED `SOLUTION_NOT_CURRENT`；状态先于开始变量核；回执与工具变量多 `solution_status`、`gate_code`（加法，其余键与码不变） | 规格第 2 项：GATED / CANDIDATE 拒，码带 gate_code |
| **路由求值回执加 `solution` 块**：新存根格式 `routing-table/v4` = `routing-table/v3` 的规则与字段 + 决策字段 `solution`——方案行 `{app_id, status, gate_code, request_contract, topics, intents, table_content_sha256}`，转接 / 资源 / 无方案行 `null`；`trace.model_source.format = "routing-table/v4"`。`routing-table/v2` / `v3` 的编译结果与 0.5.5 **逐字节相同**（表升 v3 也不变：登记字段不进这两种模型） | 规格第 2 项；回执合同按 §5.2 ③ 升名（见下「回执合同升名与下游申报」） |
| **编辑页**（`route_editor_static/editor.js`）：v3 表的方案登记每行能看能改 状态 / 闸 / 请求合同 / 话题 / 诉求；调用范围 / 优先级 / 方案包 / 交接只显示、原样带回；表里其余的键照 0.5.5 原样带回。v2 表有「升为 v3」（每个方案先当 CURRENT，写全才能存）；v3 表上新登记的应用先是 CANDIDATE；状态改成不带闸的状态时闸清空；存前先挡住 GATED 没写闸、CURRENT 没写全的项（标红）；改动列表按字段列（「状态 GATED → CURRENT」）；现存是 v3 时不载入 v2 旧版；下拉里非 CURRENT 的应用名后带状态。文字字段改完（change）重画，「检查改动并保存」跟上（以前改方案名称后按钮不亮） | 规格第 3 项的 DMN 编辑页部分（查看器的方案行编辑另单） |
| **WO-78 存前闸接入点**（只留接口，不判闸）：存表请求体可带 `gate_report`（对象 ≤ 64 KiB，必须写 `content_sha256` = 这次要存的内容摘要，否则 `STORED_TABLE_GATE_REPORT_INVALID` / `_MISMATCH`），报告存 `route-table:<表>:g:<save_id>`，存下的文档多 `gate_report_sha256`；不带报告时存下的文档与 0.5.5 相同。代码钩子 `StorageTables.save(..., gate=fn)`：`fn(clean, gate_report)` 在全部检查之后、写入之前调，抛 `RouteTableError` 即拒存（0.5.6 没有调用方传它）。编辑页可粘贴闸报告随一次保存发出 | 派单：WO-78 的存表前闸留接口 |

## 回滚

重装 0.5.5（`hu8627/dmn_json:0.5.5@0e35ef4bc3cb6032c31969413ab880141ef7793f10b51e243123e5c9278aad68`，包 sha256 `9aa92d74e6807cd48bc0a01eaa7f6ae29d206bf1af6dba6e35c8c5f682af0340`）。
**没存过 v3 表、也没有图改钉 `routing-table/v4` 时回滚无副作用**（v2 表、策略表、`route-table-index`、`gate_report_sha256` / `:g:` 键 0.5.5 都读得了或不理会）。
存过 v3 表后回装 0.5.5 会坏：0.5.5 不认识 `dmn-json.route-table/v3`——读这张表的 `evaluate_decision`（现网 DISPATCH 的 v2 存根、分诊 D 的 v3 存根）都 FAILED（`ROUTE_TABLE_INVALID`），读它的流程每次运行在路由节点失败；`invoke_solution` 全部 REJECTED，一个方案都不调；0.5.5 编辑页把它当旧格式、不能编辑；也存不回 v2（0.5.5 把 v3 当另一种表 `STORED_TABLE_SCHEMA_CHANGED`，0.5.6 也拒降级）。表在存储里原样保留，**恢复办法是重装 0.5.6**。图改钉了 `routing-table/v4` 的，0.5.5 报 `ROUTE_TABLE_STUB_INVALID`。所以存第一张 v3 表是装机之后单独的一步，要单独放行。

## 已知限制

- 与 0.5.5 相同：插件存储只有 get/set/exist，expected_version + save_id 读回是乐观并发判冲突，不是原子 CAS。
- 跨表一态只看 `dispatch.route` 和 0.5.6 起存过的路由表（`route-table-index`）；0.5.6 之前存过、之后没再存的其它路由表不在比对里（现存只有 `dispatch.route`）。索引在文档之前写，存失败时索引里多一个名字无害（读不到就跳过）。
- `SHADOW` 不在规格的四个状态里：发布线登记行有它（910769f0），且有闸 `SUPPLEMENT_DEFAULT_HOLD` 挡着一个 SHADOW 应用，为了状态与闸能来回换不丢，v3 收 `SHADOW` 并允许它带闸（被闸挡着的 CANDIDATE 写 `GATED`）。
- 编辑页只编辑路由表 v2 / v3；策略表经 `route_table_store` 工具或编辑端点同一 API 存。查看器（flow-structure-viewer）的方案行编辑不在本版。
