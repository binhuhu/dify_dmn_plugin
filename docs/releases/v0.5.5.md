# v0.5.5（候选：离线包已打，未发布、未装机）

WO-72。Brian 10-29「场景关联实体要策略配置化 同样受理  路由也是」：关键策略做成本插件里的配置表。
0.5.4 的 `decision-table/v1` 只给方案 P2 受理表用（表名必须 = `p2.` + owner.app_id，最多 128 条规则），
WO-68 的 `target.scene_entity`（182 条）与 WO-65 的 `triage.acceptance` 都存不进去。基于 v0.5.4 r2 记录提交 `59ef59d`（tag v0.5.4 = `8adb0a4`）。

## 改了什么

| 改了什么 | 为什么 |
|---|---|
| `decision-table/v1` 表名改为**闭集**，且与 owner 对应：`p2.<owner.app_id>`（照旧，方案受理表）、`target.<名称>`（owner.app_id 必须 = 定位 TARGET `56d3c0c5-4d41-4454-99ab-e3a6db6aa66c`）、`triage.<名称>`（owner.app_id 必须 = 分诊 TRIAGE `0f34962a-e380-45e1-8b35-fc64b5651776`）；`<名称>` 满足 `^[a-z0-9][a-z0-9_-]{0,47}$`。其余一律 `STORED_TABLE_NAME`，中文说明列出这三种。owner 仍恰为 {app_id, team, name}（`dmn_client/stored_tables.py`：`POLICY_OWNERS`、`decision_table_name`） | 场景关联实体、受理这类策略各一张表，归所属 workflow；名字前缀即主人，不能借名 |
| 决策表规则上限 `MAX_RULES` 128 → **512**（只这一项；路由表 128 / 4096、模板 128、参数 32、条件 32、补充 1024 场景、资源 256 目标、存表请求体 512 KiB、DSL v2 / json-table 的 128 条上限都不动） | 一场景一条规则：target.scene_entity 182 条，全部 224 个场景也装得下 |
| 路由表不能用 `target.*` / `triage.*` 这两个名字（与 0.5.3 起 `p2.*` / `supplement.*` / `*.resource` 同一条规则，拒码 `STORED_TABLE_NAME`） | 表名与格式不错配。现存路由表只有 `dispatch.route`，不受影响 |
| 路由表编辑页 `editor.js`：保存时在**载入的整份文档**上只改动过的字段；本页不管的键（`resource_table`、RESOURCE 去向、以后新增的键）和没改的路由行原样带回。RESOURCE 去向显示为「资源目标 · 编号」（以前显示成「无方案」，搜索时报错） | 清晰度评审 §4：toDoc 只写七个键，存表会丢 `resource_table` |
| `evaluate_stored_table` 工具说明补上策略表名（入参、出参不变） | 说明与能力一致 |

## 不变

存表 / 读表 / 历史 / 版本冲突检查（`route_store.run_op`、`StorageTables.save`）、`evaluate_stored_table` 的入参出参与结果信封、全部错误码、版本号规则、`content_sha256` 算法逐字不变（同一内容换表名摘要相同）。
插件全套原有测试全绿（p2.* / 路由 / 补充 / 资源）。

## 回滚

重装 0.5.4 r2（`hu8627/dmn_json:0.5.4@558244e0…`，包 sha256 `8c83147c19a85f489873cf1a62079b9199818d600b0a52a15274d73a55c010d7`）。
存进 `target.*` / `triage.*` 的表、或规则超过 128 条的 p2 表，0.5.4 读时校验不过（`STORED_TABLE_NAME` / `DECISION_TABLE_INVALID`，信封 FAILED），读它们的流程节点会失败；这些表在存储里原样保留，重装 0.5.5 即恢复。没存这类表时回滚无副作用。

## 已知限制（与 0.5.4 相同）

底层存储只有 get/set/exist；expected_version 与 save_id 检查不是原子 CAS（乐观并发 + save_id 读回判冲突）。并发创建同一缺失版本时两次保存可能都成功，后写者覆盖版本索引与 head，前写者不保证收到 409，独立的 `:s:<save_id>` 副本保留。
编辑页仍只编辑路由表 v2；策略表经 `route_table_store` 工具（维护应用）或编辑端点的同一 API 存。
