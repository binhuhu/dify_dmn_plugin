## 一、对现网的影响

**0.5.41 现网各调用形状的回答**——定位、分诊、交付编排、方案、定位查询各图里的插件节点，81 采集器与存表入口，查看器读的那些——除下面写明的，
**逐字节不变**；同一存表请求存下的表文档、内容摘要、版次与存表号不变；不带随表用例的存表不写任何新键（存储逐字节同）。证据：全链路无影响对跑闸
（老树 = 0.5.41 发布树，第十一节）；现网不调的 `convert_dmn_xml` 另取 0.5.41 金样 102 条对拍（`tests/test_v0542_goldens.py`：82 条逐字节同，
20 条不同、正好是下面几类）。

## 二、存表自动闸

（设计、两轮挑错与验收逐条见 [save-auto-gate-design.md](../save-auto-gate-design.md)、[save-auto-gate-line.md](../save-auto-gate-line.md)；
原草稿 `unreleased-save-auto-gate.md` 并进本节，下文以本节为准。）

一次存表在现有全部拒存（含 0.5.23 可调闸、0.5.41 两头核与头版闸）之后、版本核之前算好，排在它们之后才拒，三项自动核：

- **① 随表用例**：这张表随存的用例集，在内存叠一层存储（这张表读到的是这次要存的候选，别的表读现头版），照读方原路
  （`evaluate_stored_table` / `evaluate_decision` 同一个函数）逐条跑，答案按子集比期望。只拒这次存表改出来的：头版上本来就挂、答案和头版一样的
  （别的表改过之后带来的「漂移」）只报黄并点名那张表；回滚（内容等于头版之前 2 版以内的一版）只报黄。读到这张表的别的交付表的用例也跑，过不了
  只报黄。`op=cases_check` 把一次存表干跑一遍、什么都不写，回哪几条过不了、附一份照新结果改好期望的整份用例集。
  **比的是决策，不是痕迹**：v1 不比规则轨迹、模型摘要与版次、入参摘要；v2（0.5.42 修）不比决策本体的号、版次、摘要，读了什么、哪几行成立、
  链了哪几张表，结论部分不比来源（表名、版次、内容摘要）；决策集各模型同样。候选带将要存成的版次（0.5.42 修）。
- **② 跨表核**（7 张交付表）：a 场景号在场景与话题表里；b 受理条件表、场景成立表声明了 `fact:` 来源的事实，这个场景的关联实体经能力表给得出
  （B15）。按每种情形读（`when_any` 也读），只有 `eq` / `in` 算绑定场景，决策集读各模型自己的声明（0.5.42 修）。能力表是 facts 行时照核；
  **能力表是新写法（infos）时这次只报黄** `ACCEPTANCE_SUPPLIER_REGISTRY_INFOS`、不拒，facts → infos 改存不算没了供给（0.5.42 修；`1b5a91e` 把 infos 按
  `fact_id` 认，校验过的 infos 项只有 `info_id`，取到的全是空，还会挡住 facts → infos 改存）。新名能力表 facts / infos 两种都收、头版是 infos
  以后单向：首存 facts 的能力表上，受理表一声明 `fact:` 来源，`_MISSING` / `_REMOVED` 照拒。`fact:<号>` 要不要对 infos 的 `info_id` 核，第七节请 Brian 定。
  读方下读存储失败（读方自己会写成「读不出」的回执），闸照原样抛、存表回 503，不拿它当这一版改了答案或漂移（第一轮挑错 M2）。
- **③ 路由表方案现网入参**：这次改动过的方案（新增、登记改了、新有行或行的试验指着的）里**存后能调用（CURRENT）的**，读已发布版本的开始变量，
  核与登记的 `inputs` 一致。只拒变坏（0.5.42 修）：头版就能调、有行指着、登记入参没改、本来就对不上的，只报黄 `_KEPT`；紧急关闸（改成 GATED）、
  转成候选的方案不读不拒。方案真正收的请求合同本闸不核（报黄 `ROUTE_TABLE_SOLUTION_CONTRACT_UNCHECKED`，留给存后回归照 `contract_unchecked` 核）。

## 五、DMN XML

- **v1 UNIQUE 拆行导成 ANY**（0.5.41 已知限制第三条）：v1 的规则几种情形不是各列交叉时一种情形一行，几行可能同时成立，DMN 的 UNIQUE 算违例；
  ANY 收几行同时成立、输出一样（正是同一条规则的几行）。扩展元素记着原来是 UNIQUE，导回 UNIQUE；`hitPolicy="ANY"` 只收扩展元素这样记着的。
  决策集逐个模型判，提示带模型键。插件求值不变（导回仍是 UNIQUE，两条不同规则同时成立照旧 `UNIQUE_HIT_CONFLICT`）。
- **导入线对齐**（0.5.41 已知限制第四条）：导出的 XML 是表的 1.3–12 倍（实测：费用 v1 四张 2.0–5.8 倍；v2 事实 → 特征 12.4 倍，因为按号取每个号
  一列）。导入线定 4 MiB 的理由：Dify 插件一条消息最多 5 MiB，导出的回答带 XML 与模型，XML 过 4 MiB 的导出本来就送不出 Dify，所以经 Dify 送得出的
  导出都导得回；导回的表再按存表线（1 MiB）核，和存表、节点内求值同一条线。单元格线、一格写法数随之对齐；交叉先算个数再造（两格各 1024 种区间：
  先造后数本机 11 秒、峰值 100 MB，先数 0.3 秒、2 MB）。

## 五·一、按号判的表每个号没中时的结论（Brian 11-21「照这个改」）

对应 DMN 的默认输出、v1 每个决策的没中模板：v1 一张决策没有规则命中时出没中模板（state + 结果），v2 按号判以后同样的意思原来只能写成「补全
各条的否定」的兜底规则（券 v2 试点里 5 个决策补不上，号全同只有 51/300 组）。顶层规则四对照表「定义了这个号、一条规则都没中 → 未知」那一行改成：
**写了没中结论的号照没中结论给（质量已知），没写的照旧未知**。

- **写法**：决策本体 `ids` 里这个号的定义 `{type, values?, default?}`，`default = {state, value}`，可再带 `gap`（同模板的 `result.gap`）。只在原值 → 事实、
  事实 → 特征两种表上（只有它们有 `ids`）。进内容摘要（决策本体的一部分）。
- **判法**（`decision_v2.judge_keys`）：先照旧——同号异值 → CONFLICT；有判不了的规则 → INDETERMINATE；有一条成立 → 照那条规则。都不是（一条都
  没成立、也没有判不了的）时：写了 `default` 就照它给 `{quality: KNOWN, state: default.state, value: default.value, rule_id: null, filled: DEFAULT}`
  （带 `gap` 的照带），没写就照旧 `filled: NO_RULE` 未知。
- **存表核**：结构与类型在决策本体里核（`DECISION_TABLE_INVALID`）——只收 `state`、`value`、`gap`；`state` 只收规则能写的 PASS / FAIL / PENDING / UNKNOWN
  / CONFLICT / NOT_APPLICABLE；`value` 照这个号的 `type` 与 `values`（`null` 照规则那样收）。和规则的模板一样的那几条在声明检查里核
  （`TABLE_DECLARATION_INVALID`）——事实 → 特征不用 FAIL；PENDING / UNKNOWN 要带 `gap`，`gap` 的写法与在 `declare.outputs` 里声明照模板。报错的路径写
  `decision.ids.<号>.default…`。`declare.states` 照旧列规则用到的 state（没中结论的见下）。
- **没拿到的输入也会落到没中结论**（第三轮评审 M-a）：规则先问了 `quality eq KNOWN` 的，输入没拿到时这条规则是「不成立」、不是「判不了」，于是这个号
  照没中结论给、质量已知；下游按号读只看质量、state、取值，分不出是规则给的还是没中结论给的（回执里 `filled: DEFAULT` 看得出）。这和 v1 每个决策的没中
  模板一个样（v1 的「已知」条件没拿到也是不成立、出没中模板），试点照 v1 搬的就是这个意思。要「缺数据报未知」的号，另写一条「没拿到 → UNKNOWN」的规则
  （`quality ne KNOWN` 成立就出 UNKNOWN 带缺口）：有规则成立就不用没中结论。见第七节第 11 条。
- **两头核**：下游读这个号的类型照旧（只看 `type`）。
- **声明的 state**（第三轮评审 m1）：只有没中结论用到的 state 可以列进 `declare.states`，也可以不列（标准 2.0.59「declare.states 不用为 default 加」）。
- **DMN XML**：标准 DMN 的默认输出（`defaultOutputEntry`）管整张表一条没中，没有按号的，所以 `default` 记在扩展元素 `dj:decision` 的 `ids` 里、导回照旧，
  导出时提示一句（别的 DMN 引擎求值时，这几个号一条没中就没有结论）。
- **验收**：券 v2 试点的改写工具加开关、把 v1 每个决策的没中模板照搬成没中结论，五张表应与 v1 七份表逐号一致（试点会话出表，装机前对拍）。
