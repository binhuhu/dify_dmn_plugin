## 从 rc1 升级的影响

RC4 inherits RC3's existing runtime changes. Unverified `reused_from` snapshots that succeeded on RC1 now return `BLOCKED / SNAPSHOT_REUSE_UNVERIFIED`; the five reviewed calls do not contain `reused_from`. Selected-route intent completeness, nested-region validation and trusted query restrictions also changed between RC1 and RC3. Therefore five-case equivalence does not claim arbitrary RC1 compatibility.

Inherited diagnostics include `SNAPSHOT_REUSE_UNVERIFIED`, `INTENT_PATH_MISMATCH`, `PATH_ACTION_NOT_SELECTED`, `QUERY_TRUSTED_HOST_REQUIRED`, `QUERY_PAGE_BUDGET_EXHAUSTED`, `CROSSED_PARALLEL_PAIR`, `NESTED_FAILURE_PATH_REQUIRED` and `NESTED_FAILURE_PATH_MUST_CONVERGE_WITHOUT_EXECUTION`. Existing `GATEWAY_ROUTE_UNMAPPED`, `QUERY_PLAN_INVALID` and `QUERY_PARTIAL` have newly checked paths. Query trace gains a `batch` field. See [upgrade impact](../rc4-upgrade-impact.md) for scope and pinned upstream evidence.

Do not upgrade to RC3 for the missing Endpoint permission. RC4 is the reviewed candidate; the central-control owner controls installation and pinned identifier changes. Actual daemon installation → Endpoint setup → tool call is **NOT_RUN**, reserved for item 2 after item-1 acceptance. No AgentHub workflow or central-control installation was changed. Browser screenshots remain NOT_RUN due to the previously documented sandbox startup failure. No security controls were bypassed.
