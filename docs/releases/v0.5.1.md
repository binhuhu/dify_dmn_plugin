# v0.5.1（已发布，2026-10-23 UTC）
## 已知问题：并发保存不保证冲突检测（T2-12）

本版保留原始源码提交 `911c3386f4c33a9afcd7e4979453b76706f848f9`。发布前已复现：两个写入者同时创建同一个尚不存在的版本时，双方都可能返回成功；后写入者会覆盖该版本记录和当前 head，先写入者不保证收到 409。两份 `:s:<save_id>` 不可变副本仍保留。源码文档中“至多一个成功，另一个一定拿到 409”的承诺不成立；本版没有修复此问题，不能视为并发写入安全。用户在获知此问题后明确要求继续发布原定提交。

Known issue: concurrent writers creating the same missing version can both succeed. The later writer overwrites the version record and head; the first writer is not guaranteed a 409. Immutable save copies remain. This release does not fix the defect or guarantee safe concurrent writes.

在 0.5.0 之上，修全链路评审（80 `00_governance/reviews/全链路全架构评审_20261023/`，目标 T2）里路由表的四条，并落实 D8。Brian 2026-10-23：「按 0.5.1 修 T2-05、T2-06、T2-12、T2-15，按路径提交，不动 0.5.0。D8 照默认：知识库路由留在面板配置，DMN 表只放方案和转安全。」

| 编号 | 问题 | 改了什么 |

| T2-06 | v1 编译与现网 DISPATCH 的对拍测试只在维护者机器上跑 | 把现网 52df5f0d 的读回（只留 `admission-dmn` 定义包和 `admission-input` 的 REGISTRY 行，原文）提交成 `plugin/tests/dispatch_52df5f0d_readback.json`，两个对拍测试不再跳过 |
| T2-12 | 两个人同时保存会拿到同一个版本号，其中一版从历史里消失 | 每次保存带 `save_id` / `parent_save_id`，先写永不覆盖的 `:s:<save_id>`；第 n 版已被占用就 409 `ROUTE_TABLE_STALE`；写完读回版本和当前版，不是自己的就 409 `ROUTE_TABLE_RACE` |

v2 决策数据的字段因此变成：`route_state`、`route_kind`、`app_id`、`solution_name`、`solution_inputs_json`、`transfer_to`。现网还没有流程读 v2 表，没有调用方受影响。
