# v0.5.16

This release fixes stored-table declaration, overlap analysis, input validation, and receipt serialization behavior. It also restores two v0.5.14 behaviors changed by v0.5.15 input hardening.

- **Row-order shadowing follows the runtime.** The overlap check matches a scene id in either spelling (`P_02_04_01` / `M_P_02_04_01`) on `parameters.scene_id.value`, as evaluation does, so a flip hidden behind the other spelling is listed. A shadowing list longer than 100 pairs is marked `shadowing_truncated`.
- **STANDARD disposal tables can be declared with list-form states.** The no-match template (table state `NO_MATCH`) carries no `outcome`; writing one is refused.
- **List-form `states` are exactly the states the rules use.** Templates no rule points at do not count; a listed state no rule uses is refused. TRANSITION lists also name the no-match template's state. The v0.5.14 object form is unchanged.
- **Chaining accepts only decision-table and decision-set envelopes, failed ones included.** A failed envelope of another format (or one whose `model` key does not fit its format) is an input error, no longer a missing parameter.
- **A digest pin that does not match is echoed** in `source.pin` with the failure.
- **Ignored parameters are not inspected (as in v0.5.14).** With `undeclared: IGNORE`, a parameter the table does not declare may hold any JSON value, NaN or an unpaired surrogate included, without failing the call. The records a table uses must be finite, encodable JSON; otherwise the call fails with `INPUT_INVALID` on that parameter, never a crash.
- **A save body that cannot be encoded is a request error** (400 `INVALID_JSON`), not a storage fault (503).
- **A receipt always serializes.** Parameter names, model keys and other values a receipt may echo must be encodable JSON (`INPUT_INVALID` otherwise); a table name or format that cannot be encoded is not echoed.

Not changed here (DMN 2.0 step 2): COLLECT still merges hits that share a state into one output, and the hit rules are reported in `selected_rule_ids` rather than injected as `result.rule_id`. Solution-layer table names are not in this release. Production installation and acceptance have not been completed.
