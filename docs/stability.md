# 架构稳定性评估与落地边界

## 结论

结构适合候选试点：查询和决策共享显式 Step 合同，定位一个 Phase，解决问题 P1–P7；每个 Phase 可以交错多个 query/decision Step。Dify 仅做工具接入，DMN 和能力契约由版本固定的服务统一执行。这一结构避免把规则隐在提示词或插件核心中。

当前评级是**可运行候选原型，尚未生产验收**。稳定性主要风险是 JS 引擎标准语义覆盖和真实能力合同缺口，不是是否能调用 HTTP。

## 已落的防护

- 每请求全新 OS 子进程，5 秒硬 SIGKILL，128 MiB V8 old-space 上限；CPU 死循环无法阻塞服务健康检查
- 父服务并发 2、无排队；满额 503；上传先占槽且受 5 秒上传时限；请求退出清理子进程和槽位
- 无自动重试：避免重复取数和复用旧事实；调用方决定重试并用新证据
- 子进程只继承 TZ/LANG，不继承 API token、Dify secrets 或宿主环境
- 服务 bearer 验证、无请求正文/模型/原始参数日志、默认 loopback；插件禁重定向和环境代理，明确允许内网 HTTP 才能使用
- 模型与依赖固定 hash/version；不从模型加载网络资源、代码、imports 或动作
- Docker 示例加入非 root、只读、CPU/总内存/pid 限制、内部网络和重启策略

子进程和 V8 内存限制并不是完整恶意多租户沙箱；进程仍与服务共享 OS 用户/文件读取权限。生产应在隔离容器运行并执行镜像扫描/补丁更新。容器总内存限制兜住 V8 以外分配；不能只靠 old-space 限制声称内存绝对隔离。

## 稳定输出

- 单决策：SUCCEEDED / FAILED 分开于业务值；result_state区分 NULL / VALUE / UNAVAILABLE
- 查询：FOUND / NOT_FOUND / UNKNOWN / QUERY_TIMEOUT / ERROR 不合并；技术状态单独携带
- 计划：SUCCEEDED / WAITING_INPUT / FAILED；每个 Step 保留身份、依赖、结果状态与 trace
- trace不包含原始查询参数和引擎依赖绑定值；计算结果仍属于业务数据，宿主 UI 应按正式结果合同选择展示
- P6/P7 只产生建议，不下单、补券、改金额或写工单

## 未闭合的生产门

1. 提供并核对正式 identity/binding/scene-result.v2 JSON schema；当前 candidate 输出不能当兼容证明
2. 接入真实只读能力，逐项固定实现单元、标准化参数映射、响应路径、确认度、时效、取数证据；mock 不是实测来源
3. 接入经过审定的 L1 ESM 事实计算器；不能执行工作流任意传入的 JavaScript
4. 提供真实场景定位与 P1–P7 DMN 及版本；用独立历史案例、原始运行记录、边界/故障用例回归；不得修改在产基线来凑通过
5. 对金额、日期、集合、空值、UNKNOWN、漏斗、优先关系进行场景级测试；尤其检查 IEEE-754 与上游 FEEL 差异
6. 真实 Dify 安装/调用、受控网络、HTTPS、容量/长时间稳定性和宿主 UI 验收；最终投产由负责人批准

## 复核记录

已有独立源码核查揭示并处理：FEEL warnings被上游丢弃、规则缺格静默命中、未识别 typeRef透传、输出枚举未强制、trace仅matched而非selected、同步循环无法同事件循环超时。当前 profile通过严格适配/预校验拒绝或显式标出上述边界。

本地测试证明的是上述代码路径，不证明真实客服判断质量，亦不证明高负载或恶意多租户安全。
