# 开源与付费产品范围

目标是把 SOP 拆解、筛重、多源冲突裁决、标准方案治理与执行带入 Dify。LOCATE 以一个业务模式一个逻辑入口组织定位，SOLVE 支持多个方案；Phase/Step 是结构容器，Query/Decision/Gateway/Execute/Wait/Result 是执行节点，Decision 的 state/data/actions 分开。这是产品方向，不能作为现有全量实现声明。

## 当前开源范围

本修订中已有的项目材料整体按 AGPL-3.0-only 提供：Python 外部 XML 封装与内置 JSON 插件、Node 引擎、只读查看器、适配与参考宿主、合同/示例、测试和构建脚本。第三方材料另按原许可。没有通过本次许可变更把现有功能移出开源范围。

main 0.4.0-rc3 提供只读结构查看、有限 JSON 决策与受控查询基础、独立 XML/FEEL 引擎及参考运行基础。只读查看器不编辑或持久化规则；合成查询不代表真实业务接入；处置建议不代表赔付、改票或工单履约。当前已完成与尚未完成的验收以技术文档为准。

## 可以准备的付费交付

| 交付 | 可以约定的内容 | 必须明确的边界 |
| --- | --- | --- |
| 商业软件许可 | 特定组件、版本的修改/集成/分发/托管权 | 先核验 Brian Hu 权利；第三方义务继续有效 |
| 试点实施 | 部署、SOP/规则建模、接口适配、回归和培训 | 范围与验收用例逐项约定；真实数据和写操作另授权 |
| 维护支持 | 问题响应、升级协助、约定修复范围 | SLA、支持版本、期限另签；可搭配 AGPL 使用 |
| 后续企业能力 | 新模块或定制能力的设计/研发 | 先定义并交付验收，不宣称已经可用 |

推荐先准备一份有边界的试点交付清单与商业许可选项，由实际需求确定报价；目前不设虚构价目、客户案例、ROI 或付费验证结果。

## 后续迭代与企业范围

0.4.x 修复和 RC 发布由独立验收分支推进。0.5.0-dev 目标是在插件内加入友好表格/结构编辑、校验、纯决策试算与版本冻结；不是本次 PR 的交付。未来企业能力可考虑 chat、异步任务、人工工作台共享案件和版本，以及审批、审计、权限、发布/回滚、长期任务和标准方案治理；这些尚待设计与验收。

未来独立企业模块是否使用商业条款须单独确定，并核验原创来源及与 AGPL 核心的组合方式。不能把依赖或未经授权的社区代码简单换成闭源许可。已按 AGPL 发布的修订仍保留已授出的 AGPL 权利。
