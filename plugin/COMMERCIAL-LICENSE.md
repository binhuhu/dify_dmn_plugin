## 如何申请

在 [binhuhu/dify_dmn_plugin 的 GitHub Issues](https://github.com/binhuhu/dify_dmn_plugin/issues) 提交不含机密的商业授权咨询，说明使用场景、拟授权组件及版本、是否修改/分发/托管、部署和客户范围、所需支持。Brian Hu 与申请方另行确认私下沟通渠道；不要公开合同、身份文件、客户数据或凭据。

商业授权只有在双方签署约定的书面协议并满足其生效条件后成立。本文件、Issue 回复、报价讨论、仓库访问、下载、赞助和付款意向均不自动授予商业许可。目前没有公开定价、已签客户记录或默认 SLA。

## 可商议的授权形态

| 形态 | 合同需明确的范围 |
| --- | --- |
| 企业自用 | 被授权法律主体、关联方、环境/实例范围、允许修改的组件、期限 |
| OEM / 集成分发 | 产品、客户范围、嵌入和分发权、下游许可条件、支持责任 |
| 托管 / SaaS | 托管运营主体、服务产品、租户/容量计量、网络使用及修改权 |
| 付费支持与交付 | 部署、培训、规则建模、验收、维护；可以搭配 AGPL 或商业许可 |

授权计量、费用、续期、版本升级和服务响应须写入具体合同，不预设数值。商业合同应列明源码提交、包/镜像摘要和排除的第三方材料。只签订维护服务不等于获得闭源再许可。

商业政策仅适用于带本声明的修订。历史 Release、包和哈希保持原记录；不得把新声明回写为旧包的发布许可。后续新许可包应使用新版本、源码提交及摘要，以便与旧包区分。
